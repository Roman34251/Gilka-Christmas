# Гілка свята

React-магазин на Cloudflare Workers. Товари, реальні фото й ціни — у Sanity. Node.js 24 потрібен для збірки.

## Реалізовано

Головна з фотобанером, чотири категорії, пошук, сортування, наявність, окремі сторінки товарів із галереєю та характеристиками, кошик у браузері, оформлення без реєстрації, доставка Новою поштою, післяплата та серверна інтеграція еквайрингу monobank. Є інформаційні сторінки, 404, sitemap, індивідуальні заголовки сторінок, адаптивність і підтримка reduced motion.

## Локальна робота

У корені проєкту:

```powershell
npm ci
npm test
npm start
```

Адреса — http://localhost:4173. `npm start` збирає проєкт і запускає Wrangler. `npm run build` створює `dist/worker.js` та `dist/assets`. Фото стискаються у WebP під час збірки. Секрети з `.env` / `.dev.vars` не потрапляють у Git.

Для демонстрації інтерфейсу з прикладами товарів:

```powershell
npm run build
npx wrangler dev --port 4173 --var SANITY_PROJECT_ID:
```

Демо-режим чітко позначений і не приймає реальних замовлень. У production порожній Sanity показує порожні категорії, а не вигадані товари.

## Публікація через GitHub / Cloudflare

- Назва Worker: `gilka-christmas`.
- Корінь: корінь репозиторію.
- Build: `npm run build`.
- Deploy: `npx wrangler deploy`.
- Preview: `npx wrangler preview`.
- Змінна збірки: `NODE_VERSION=24`.

Після публікації перевірте головну, пряме посилання на товар, кошик та оформлення. Саме оновлення коду не активує приймання замовлень: потрібні налаштування з `LAUNCH.md`.

## Sanity Studio

Адмінпанель товарів — папка `studio`, публікується окремо від магазину. Після `npm ci` у цій папці можна запускати `npm run dev` або `npm run deploy`. Нові поля: категорія зі списку, slug, артикул, попередня ціна, наявність, характеристики, галерея. Старі категорії текстом також розпізнаються. Відсутність slug не ламає посилання: використовується ID документа.

Товари оновлюються після Publish у Sanity й перезавантаження сторінки магазину. Жодні замовлення або дані покупців не записуються у публічний Sanity dataset.

## Замовлення та платежі

- Замовлення зберігаються в приватній Cloudflare D1, binding `ORDERS_DB`.
- Активатор продажів: `ORDERS_ENABLED=true`.
- Секрет банку: `MONO_TOKEN`; лише на сервері.
- API рахує суму за цінами Sanity у копійках, перевіряє кількість і наявність.
- Повторний запит із тим самим ключем повертає попереднє замовлення.
- Банківський webhook не є джерелом істини: сервер запитує поточний статус через API банку й перевіряє ID, суму, валюту та дату.
- Після неоднозначного таймауту створення інвойсу статус `invoice_review`. Автоматично новий інвойс не створюється, щоб не допустити подвійної оплати.
- Статус покупця захищений випадковим токеном, який зберігається у sessionStorage; у базі — лише SHA-256. На іншому пристрої потрібно звернутися до магазину.
- Приймання замовлень на ікру додатково потребує `FOOD_SALES_ENABLED=true` після заповнення інформації та погодження логістики.

Окремого кабінету менеджера, автоматичних ТТН Нової пошти, резервування залишків і автоматичної фіскалізації ця версія не містить. Точка доставки вводиться вручну. Замовлення доступні власнику через захищену панель Cloudflare D1; спосіб щоденної обробки варто узгодити перед активацією продажів.

## Перевірки

`npm test` перевіряє розрахунок ціни, кількості, контакти, доступність, ідемпотентність, доступ до замовлення, стан конфігурації, інвойс/статус банку та таймаути. Тести працюють із локальним SQLite й підставними відповідями банку; реальних платежів не виконують.

Дизайн і сценарії: `DESIGN.md`. Підключення до продажів: `LAUNCH.md`.
