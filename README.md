# Гілка свята

React-магазин із серверним формуванням каталогу в Cloudflare Workers і товарами в Sanity. Node.js 24 потрібен для локальної збірки. На хостингу код виконує Cloudflare Workers.

## 1. Що де знаходиться

Є три окремі частини: **магазин** для покупців на Cloudflare, **Studio** для редагування товарів у браузері та **хмарне сховище Sanity** для самих товарів і фотографій. GitHub зберігає код, а не ваш каталог товарів.

### Папки, які створюються автоматично

Зараз після очищення цих папок немає. Їх не потрібно створювати вручну.

| Шлях | Що це | Як відновлюється |
|---|---|---|
| `node_modules/` | Бібліотеки магазину та інструменти збірки. | `npm ci` в корені проєкту. |
| `dist/` | Готовий сайт: `worker.js` — сервер, `assets/` — браузерний JavaScript, CSS, фото і SVG. | `npm run build` в корені після встановлення бібліотек. |
| `studio/node_modules/` | Бібліотеки адмінпанелі. | `npm ci` у папці `studio`. |
| `studio/dist/` | Готова до публікації адмінпанель. Це інша збірка, тому раніше було дві папки `dist`. | `npm run build` або `npm run deploy` у папці `studio`. |
| `studio/.sanity/` | Тимчасові файли інструментів Sanity. | Створюються інструментами Studio за потреби. |
| `.wrangler/` | Кеш і локальні службові дані інструмента Cloudflare. | Створюються Wrangler за потреби. |

`.env*` і `.dev.vars*` у `.gitignore` — шаблони назв файлів, а не папки. Зірочка означає будь-яке продовження назви. `.dev.vars` можна використовувати для локальних змінних Worker; наразі його немає. Видаляти налаштування разом із кешем не потрібно.

## 3. Як зберігаються товари: база і архітектура

**Окрему NoSQL-базу встановлювати або програмувати для поточного каталогу не потрібно.** Sanity надає хмарне сховище Content Lake: кожен товар зберігається як документ із полями. SQL-таблиці створювати не потрібно. Документи мають ідентифікатор `_id` і тип `_type`. [Офіційне пояснення документів Sanity](https://www.sanity.io/docs/content-lake/documents).

У нашій конфігурації проєкт — `fcl0yp5j`, dataset — `production`. Dataset — окремий набір даних усередині проєкту. Набір `tree`, який був на скриншоті, цей код не використовує. Studio та магазин повинні працювати з одним dataset, інакше додані товари не з’являться на сайті.

Структуру товару вже описано у `studio/sanity.config.js`:

| Поле | Що зберігає |
|---|---|
| `_type: product` | Позначає документ як товар. |
| `name` | Назву. |
| `category` | Категорію одним текстовим значенням; сайт формує з категорій фільтр. |
| `price` | Число — ціну в гривнях. |
| `detail` | Текст опису, матеріалу й розміру. |
| `gallery` | Упорядкований список посилань на зображення. Перше — обкладинка. |

Файли фото завантажуються у сховище Sanity і доставляються через його CDN — мережу роздачі файлів. У документі товару зберігаються посилання на записи зображень. [Як Sanity зберігає файли](https://www.sanity.io/docs/content-lake/assets).

Опис полів у Studio — це налаштування форми і перевірок редактора. Він не створює товари автоматично і не є жорсткою SQL-схемою бази. Майбутній імпорт фіда також має перевіряти дані перед записом.

Порядок роботи:

1. Відкриваєш Studio, створюєш «Товар», заповнюєш поля й додаєш фото.
2. Натискаєш **Publish**. Sanity зберігає опублікований документ у `production`; чернетки магазин не показує.
3. Покупець відкриває сайт. Cloudflare Worker через API — програмний інтерфейс Sanity — запитує опубліковані товари.
4. Worker формує сторінку, браузер завантажує її та фото. React забезпечує фільтри і кошик.

Схема: **Studio → Sanity (товари й фото) → Cloudflare Worker → сторінка покупця**. Фото браузер завантажує за адресами Sanity.

Після зміни ціни чи фото не потрібно перебудовувати сайт: наступний запит сторінки читає опубліковані дані. Зміни дизайну потребують нової публікації магазину. Зміни полів форми потребують публікації Studio, а для показу нових полів на сайті — також відповідних змін магазину.

## 4. Що робити далі по порядку

1. **Підтвердити робочу адресу Studio.** Налаштована адреса зараз повертає 404; потрібен результат успішного деплою або адреса з розділу Studios.
2. **Додати один справжній товар через форму і натиснути Publish.** Створювати ще одну базу не потрібно.
3. **Відкрити магазин на Cloudflare й перевірити цей товар:** ціну, категорію, обкладинку і порядок фото. Це перевірить весь шлях від CMS до покупця.
4. **Пізніше узгодити імпорт фіда.** Зараз імпорт не реалізований. Для нього потрібно визначити сталий ідентифікатор товару, відповідність полів і правила оновлення ціни, категорій та порядку фото. Це дозволить оновлювати наявні товари без дублікатів.

Поточна модель містить лише каталог. Кошик зберігається в браузері; замовлення, оплата, складські залишки та варіанти товарів поки не реалізовані.

## Публікація через GitHub і Cloudflare

Оновіть файли в репозиторії GitHub, включно з package.json, package-lock.json, build.mjs, server.mjs і wrangler.jsonc. Конфігурація Wrangler має бути в корені репозиторію, поруч із package.json.

На екрані Cloudflare Create an app для репозиторію Gilka-Christmas задайте такі значення.

| Поле | Значення |
|---|---|
| Project name | gilka-christmas |
| Root directory | корінь репозиторію, залишити стандартне значення |
| Build command | npm run build |
| Deploy command | npx wrangler deploy |
| Build variable NODE_VERSION | 24 |

Cloudflare встановить залежності, збере React і серверний код, потім опублікує Worker. Після успішного деплою скопіюйте фактичну адресу із панелі Cloudflare. Назва gilka-christmas збігається з полем name у wrangler.jsonc.

Файл wrangler.jsonc містить публічний ідентифікатор Sanity fcl0yp5j та dataset production. Токен для читання публічного каталогу не потрібен. Поле ORDER_EMAIL можна додати до vars у цьому файлі, щоб активувати надсилання списку через поштову програму покупця. Адреса продавця буде публічною.

## Локальна перевірка

`node_modules` і `dist` можна видаляти з комп’ютера: це встановлені бібліотеки та результат збірки. Вони відновлюються послідовністю `npm ci`, потім `npm run build` у корені проєкту. Без першої команди після видалення `node_modules` збірка не запуститься. Для роботи локального сайту ці папки знову знадобляться.

Не видаляйте `package.json`, `package-lock.json`, `build.mjs`, вихідний код, `public` і `wrangler.jsonc`: з них хостинг відтворює сайт. Видалення локальних згенерованих папок не видаляє вже опублікований сайт або товари в Sanity. `.gitignore` лише виключає файли з Git; він нічого не видаляє і може містити назви папок, яких зараз немає.

У корені проєкту виконайте npm ci, потім npm start. Відкрийте http://localhost:4173. Команда запускає збірку і локальне середовище Cloudflare Workers. Локальний .env може перевизначити параметри Sanity. Файли .env та .dev.vars залишаються локальними.

Команда npm run build створює dist/worker.js і dist/assets. Збірка не потребує доступу до Sanity. Каталог завантажується під час запиту до сайту, тому оновлення товару через Publish видно після оновлення сторінки.

Для перевірки готовності до публікації виконайте npx wrangler deploy --dry-run. Команда npm run deploy збирає та публікує сайт із комп’ютера і потребує входу Cloudflare.

## Адмінпанель Sanity

Studio знаходиться в окремій папці studio. У ній є власні команди npm run dev та npm run deploy. Деплой Studio і деплой магазину виконуються окремо.

Після очищення локальні залежності й збірку Studio видалено. Перед наступним локальним запуском або публікацією адмінпанелі виконайте npm ci у папці studio. Потім використайте npm run dev або npm run deploy. Згенеровані папки відновляться автоматично. Магазин отримує товари безпосередньо з API Sanity.

Обидві частини використовують проєкт fcl0yp5j та dataset production. У Studio відкрийте «Товар», заповніть назву, категорію, ціну, опис і фото та натисніть Publish. Порядок фото визначає галерею, перше фото є обкладинкою. Категорії формують фільтри магазину.

## Поведінка сервера

- Головна сторінка містить готовий HTML каталогу та React-код для взаємодії.
- /api/products повертає опубліковані товари.
- Фото, CSS і браузерний JavaScript роздаються через Cloudflare Static Assets.
- Збій Sanity повертає 503, а відсутній маршрут — 404.
- При налаштованому Sanity порожня база показує «Колекція готується».
- Демонстраційні товари використовуються лише за відсутнього SANITY_PROJECT_ID. Налаштований production-проєкт читає реальну базу.
- Кошик зберігається в браузері. Платіжний сервіс, приймання замовлень і імпорт фіда потребують окремого підключення.
