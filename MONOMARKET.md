# Ціни Monomarket

Загальний прайс без доставки: `GET /api/prices` (також `HEAD`). Відкритий доступ, лише публічні роздрібні ціни з бази; поля `id`, `code`, `sku`, `name`, `price`, `old_price`, `availability` у масиві `data`. Зміни цін враховуються при кожному запиті. Для Rozetka й Епіцентру можна використовувати відповідні XML-фіди або цей загальний прайс.

Маршрут: `GET /api/monomarket-price` (також підтримує `HEAD`). Прайс читає опубліковані товари й документи `deliveryTier` з Sanity при кожному запиті. У JSON повертає `updatedAt`, `total`, `data`. `code` збігається з ID товару в `feeds/monomarket.xml`.

Ціни всіх товарів у Sanity одноразово підвищено на 15% 16.11.2026, з округленням до копійок. Позначка `priceAdjustment = 2026-11-16-markup-15` захищає повторний запуск цієї операції. Endpoint не застосовує націнку повторно.

Monomarket отримує поточну ціну товару з бази плюс доставку. Для Rozetka, Епіцентру та сайту використовується лише поточна ціна товару. Для вінків і прикрас доплати за доставку немає.

| Висота ялинки до, включно | Доставка, грн |
| --- | ---: |
| 1,5 м | 300 |
| 1,8 м | 500 |
| 2 м | 600 |
| 2,1 м | 700 |
| 2,2 м | 700 |
| 2,3 м | 1000 |
| 2,5 м | 1300 |
| 3 м | 1500 |

Тарифи зберігаються окремими документами «Доставка для Monomarket» в Sanity Studio. Для проміжного розміру береться наступна межа. Для ялинки без висоти або вище найбільшої межі прайс повертає 503, щоб не передавати ціну з помилковою доставкою.

Підсумкова ціна обчислюється при запиті, тому зміна ціни товару чи тарифу в адмінпанелі одразу враховується без повторного запису всіх товарів. Дубль підсумкової ціни в базі не потрібен.

## Доступ і публікація

У Cloudflare має бути секрет `MONOMARKET_FEED_TOKEN`. Клієнт передає його як `Authorization: Bearer …` або параметр `token` у посиланні. Без налаштованого секрету маршрут повертає 503, з неправильним токеном — 401. Відповіді не кешуються.

`MONOMARKET_WAREHOUSE_ID` задає фактичний склад з кабінету Monomarket. За відсутності значення `warehouses` порожній. Поточна конфігурація залишку, гарантії, оплати частинами та строку відправлення — `feeds/config.json`, розділ `monomarket.price`; залишок умовний, не інтегрований зі складським обліком.

Формат JSON успадковано від наявної реалізації проєкту. Приймання прайсу в кабінеті Monomarket ще потребує перевірки за документацією продавця, зокрема налаштування складу й способу авторизації.

Після схвалення публікації: оновити фіди, зібрати сайт, встановити секрет і опублікувати Worker. На опублікованому маршруті перевірити 401 без токена, 200 з токеном, кількість товарів та ціну кожного розміру. Потім підключити URL у кабінеті Monomarket.
