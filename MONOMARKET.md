# Ціни Monomarket

Загальний прайс без доставки: `GET /api/prices` (також `HEAD`). Відкритий доступ, лише публічні роздрібні ціни з бази; поля `id`, `code`, `sku`, `name`, `price`, `old_price`, `availability` у масиві `data`. Зміни цін враховуються при кожному запиті. Для Rozetka й Епіцентру можна використовувати відповідні XML-фіди або цей загальний прайс.

Маршрут: `GET /api/monomarket-price` (також підтримує `HEAD`). Прайс читає опубліковані товари й документи `deliveryTier` з Sanity при кожному запиті. У JSON повертає `updatedAt`, `total`, `data`. `code` збігається з ID товару в `feeds/monomarket.xml`.

Ціни всіх товарів у Sanity одноразово підвищено на 15% 16.11.2026, з округленням до копійок. Позначка `priceAdjustment = 2026-11-16-markup-15` захищає повторний запуск цієї операції. Endpoint не застосовує націнку повторно.

Monomarket отримує поточну ціну товару з бази плюс доставку. Для Rozetka, Епіцентру та сайту використовується лише поточна ціна товару. Для вінків і прикрас доплати за доставку немає.

| Точна висота ялинки | Доставка, грн |
| --- | ---: |
| 1,5 м | 300 |
| 1,8 м | 500 |
| 2 м | 600 |
| 2,1 м | 700 |
| 2,2 м | 700 |
| 2,3 м | 1000 |
| 2,5 м | 1300 |
| 3 м | 1500 |

Тарифи зберігаються окремими документами «Доставка для Monomarket» в Sanity Studio. Для кожної висоти ялинки потрібен окремий тариф. Якщо висоти немає або для неї немає тарифу, відповідна позиція пропускається в прайсі.

Підсумкова ціна обчислюється при запиті, тому зміна ціни товару чи тарифу в адмінпанелі одразу враховується без повторного запису всіх товарів. Дубль підсумкової ціни в базі не потрібен.

## Доступ і публікація

У Cloudflare має бути секрет `MONOMARKET_FEED_TOKEN`. Клієнт передає його як `Authorization: Bearer …` або параметр `token` у посиланні. Офіційні сервери Monomarket допускаються за заголовком Cloudflare `CF-Connecting-IP` (список IP з офіційної довідки від 16.11.2026). Для решти запитів без налаштованого секрету маршрут повертає 503, з неправильним токеном — 401. Заголовок `X-Forwarded-For` для авторизації не використовується. Відповіді не кешуються.

`MONOMARKET_WAREHOUSE_ID` задає фактичний склад з кабінету Monomarket. За відсутності значення `warehouses` порожній. Поточна конфігурація залишку, гарантії, оплати частинами та строку відправлення — `feeds/config.json`, розділ `monomarket.price`; залишок умовний, не інтегрований зі складським обліком.

Формат JSON звірено з довідкою кабінету продавця 17.11.2026. Поля `price` й `old_price` передаються в цілих гривнях (округлення до найближчої гривні); у базі ціни залишаються з копійками. Без заданої локації масив `warehouses` порожній; налаштування локацій потребує фактичних даних продавця.

Після схвалення публікації: оновити фіди, зібрати сайт, встановити секрет і опублікувати Worker. На опублікованому маршруті перевірити 401 без токена, 200 з токеном, кількість товарів та ціну кожного розміру. Потім підключити URL у кабінеті Monomarket.

## Виправлення фото 17.11.2026

18 додаткових фотографій вінків і гірлянд перенесено у Sanity. Посилання зберігаються в полі `marketplaceGallery` відповідних товарів, додаються до основної галереї при генерації фідів і не впливають на галерею сайту. Генератор більше не створює посилань на локальні `/feeds/photos/`, яких може не бути під час наступного розгортання. Штатний генератор `door-photos.mjs` залишено для відновлення матеріалів; одноразовий перенос виконує `repair-marketplace-photos.mjs` з резервною копією та перевіркою версій документів.

Змінні, введені власником у панелі Cloudflare, зберігаються під час публікації завдяки `keep_vars: true` у `wrangler.jsonc`. Токен рекомендується зберігати як Secret; Text також читається Worker, але доступний для перегляду в налаштуваннях. Власник залишив свій новий ключ 17.11.2026; локальний ключ не використовується для перезапису віддаленого. Повне підтвердження приймання прайсу очікує наступної синхронізації Monomarket.
